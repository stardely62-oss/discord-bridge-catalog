# Безопасность каталога

## Как защищена подпись
- Приватный ключ — только секрет окружения `catalog-publish`. Окружение требует одобрения владельца и разрешено только для `main`; workflow `Publish` перед подписью проверяет, что эти правила включены, иначе останавливается.
- `Publish` состоит из четырёх изолированных job:
  1. **build** — сборка и проверки этого коммита (serial растёт, правило версий наборов). Без ключа, токен только на чтение.
  2. **sign** — в окружении `catalog-publish`. Запускается только `scripts/sign.mjs` встроенным в runner Node: без npm, без сборки, без сторонних Actions. Подписывается манифест, чей SHA-256 сообщил build (через выходы job, не через хранилище артефактов). Ключ должен совпадать с `keys/catalog-public-key.b64`. Наружу уходит только `catalog.signed.json`.
  3. **verify** — подпись закреплённым ключом, размер и SHA-256 данных, serial.
  4. **publish** — единственный job с правом записи: без ключа, без checkout и сборки; существующий релиз не заменяется.
- Все Actions закреплены по полному SHA; `checkout` не сохраняет токен. Политику проверяет `scripts/ci/check-workflows.mjs` (тот же, что в приложении) на каждом PR.

## Правила для участников
- Пулреквест проходит `Validate` (данные, правило версий, детерминированная сборка) и `security` (gitleaks, приватные ключи, почта коммитов, политика workflow). Секретов в PR нет: `pull_request_target` запрещён, токен только на чтение.
- PR участника не может менять `.github/`, `scripts/`, `keys/`, `package*.json` и `.gitleaks.toml` — `Validate` отклоняет такой PR (это делает только владелец).
- Workflow из форков запускаются только после одобрения владельцем (Settings → Actions → «Require approval for all external contributors»).
- Публикует только владелец: ручной запуск `Publish` + одобрение окружения. Перед одобрением проверьте, что в запуске тот коммит `main`, который вы просмотрели.
- Коммиты — с noreply-адресом GitHub (`<id>+<login>@users.noreply.github.com`); проверка выводит чужие адреса только в маскированном виде.

## Сообщить об уязвимости
Через приватный Security Advisory репозитория (вкладка Security → Report a vulnerability), не через публичный issue.
