# Каталог Discord Bridge

Подписанный каталог наборов адресов — приложений, игр и сервисов — для
[Discord Bridge](https://github.com/stardely62-oss/discord-bridge). Здесь только данные:
домены, IP-сети, описания и значки. Каталог не может передать в приложение
исполняемые файлы, скрипты или команды winws.

## Как устроено

| Путь | Что это |
|---|---|
| `packs/<id>.json` | набор; формат — `schemas/pack.schema.json` (схема 1) |
| `icons/*.png` | значки (PNG/WebP, до 64 КБ и 512×512, без SVG); источники — `icons/SOURCES.md` |
| `keys/catalog-public-key.b64` | открытый ключ, который закреплён в приложении |
| `scripts/build.mjs` | проверка и детерминированная сборка снимка |
| `scripts/sign.mjs` | подпись манифеста Ed25519 |
| `scripts/check-versions.mjs` | правило версий: адреса меняются только с новой `version` |

Публикация — это релиз `catalog-<serial>` с двумя файлами:

- `catalog-data.json` — все наборы и значки (base64) одним файлом;
- `catalog.signed.json` — подписанный манифест. В нём `kind: discord-bridge-catalog`, номер `serial` (время коммита, растёт только вверх), размер и SHA-256 файла данных, число наборов и значков.

Приложение берёт `releases/latest/download/catalog.signed.json`. Затем оно:

1. проверяет подпись закреплённым ключом;
2. проверяет формат и совместимость;
3. скачивает данные только из релиза с тем же `serial`;
4. сверяет размер и SHA-256;
5. заново проверяет каждый набор и каждый значок.

Каталог старше уже принятого не принимается. Если что-то не так, приложение
продолжает работать с последним проверенным каталогом или со встроенным.

## Правила наборов

- `id` стабилен и совпадает с именем файла. При любом изменении набора увеличивайте `version` и `updated`.
- Изменение доменов или IP без увеличения `version` и уменьшение `version` отклоняются автоматически (`scripts/check-versions.mjs`). Сравнение идёт с базовой веткой и с последним опубликованным каталогом, подпись которого проверяется закреплённым ключом, поэтому правило не обходится переписыванием истории. Адреса сравниваются нормализованными: порядок, регистр и повторы не считаются изменением. Описание и значок можно менять без новой версии — приложение всё равно подтверждает установку по точному SHA-256 набора.
- Только проверяемые адреса. IP-сети — только с источником в `provenance` (`kind: ips`) и не шире `/8` для IPv4 и `/16` для IPv6. Выдуманные или «примерные» IP недопустимы.
- Если домены помогают не полностью, укажите `partialCoverage` и объясните это в `notes`.
- `ports` — порты собственного трафика сервиса, если они известны и подтверждены источником: `{"udp": "5055-5058"}`, `{"tcp": "443,4530"}`. Синтаксис как у `--filter-tcp`/`--filter-udp`, без пробелов, не больше 32 элементов. Это только описание: приложение (с 0.1.4) проверяет, обрабатывает ли эти порты выбранная стратегия, и подсказывает пользователю, если нет. В winws из каталога по-прежнему ничего не передаётся. Более старые версии приложения поле игнорируют.
- `flowsealList` — только для сервисов, уже входящих во встроенные списки Flowseal. Такой набор не устанавливается и не означает, что сервис доступен.
- Никаких рейтингов и обещаний «работает».

## Безопасность

Как изолирован ключ подписи, какие проверки идут в PR и какие правила для участников — в [SECURITY.md](SECURITY.md).

## Вклад сообщества

Пулреквест проходит проверки `Validate` и `security` и ревью владельца. Подписи и
секретов в пулреквестах нет; менять скрипты, workflow и ключи может только владелец.

## Публикация (владелец)

1. Один раз: **Settings → Environments → New environment `catalog-publish`**:
   - **Required reviewers** — вы;
   - **Deployment branches** — только `main`;
   - секрет окружения `CATALOG_SIGNING_KEY` — base64 32-байтового seed Ed25519, парный `keys/catalog-public-key.b64`.
2. После слияния изменений в `main`: **Actions → Publish signed catalog → Run workflow**.

Без секрета или с ключом, не совпадающим с закреплённым, публикация останавливается.

Смена ключа: добавьте новый открытый ключ в `CATALOG_TRUSTED_KEYS` приложения, выпустите приложение, затем замените ключ здесь.
